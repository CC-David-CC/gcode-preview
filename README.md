# G-code Preview

Use **Try example** to view a small example, or **Open from My files** to choose a `.gcode`, `.gco`, or `.nc` file. To bring a file from your computer, upload it in Files first. Files can also open a supported file directly in the viewer. Drag to rotate and scroll or pinch to zoom. The non-extruding moves switch can reveal travel paths, including movement in many CNC files.

The visualization runs in the visitor's browser using `gcode-preview` and WebGL. It does not edit or save G-code or connect to a machine. The fixed 220 × 220 × 250 mm grid is illustrative, not a detected printer profile. This is not a complete printer or CNC simulator, a machine compatibility check, or a safety guarantee. The underlying library is primarily designed for 3D-printing G-code and may omit or interpret commands differently from a particular controller. Verify toolpaths and machine settings with appropriate tools before running hardware.

Unsupported or unreadable files leave the previous preview in place. Numbered commands, multiple commands on one line, coordinate-only modal lines, coordinates on unit or positioning-mode lines, arc-center mode changes, full-circle arcs, coordinate-system selection, tool offsets, non-XY arc planes and homing after a move are rejected because this viewer cannot reliably represent them. It starts at XYZ zero with millimeter units and no stored machine offsets; an initial homing command is not simulated. The worker converts G20/G21 inches and millimeters, G92 X/Y/Z coordinate resets, and G90/G91 absolute and relative XYZ movements to millimeter positions before rendering and layer grouping. G92.1–G92.3 are rejected. This follows the basic [Marlin G20](https://marlinfw.org/docs/gcode/G020.html) and [G92](https://marlinfw.org/docs/gcode/G092.html) semantics; other controller dialects and persistent offsets can differ. It treats extrusion mode separately: M82/M83 select absolute/relative E and G90/G91 do not change E mode. Controllers can differ. For path coloring, the worker estimates extrusion from M82/M83, G92 E and per-tool E values; decreasing absolute E is treated as retraction. Controller-specific extrusion behavior and actual deposited material are not simulated. These checks do not detect every unsupported command or controller behavior. Files up to the shared 128 MiB limit are accepted. Parsing runs in a cancellable per-window worker; transferring the parsed commands and drawing their geometry still use the UI thread and memory. Large files can remain slow or exhaust device memory. A local worker test parses 100,000 moves and cancels a 500,000-move parse while the desktop remains responsive; it does not establish a 128 MiB device capacity. The example, upload, account/server sync, unsupported-file recovery, visual travel switch, close/reopen and fresh-session workflow were tested at desktop and emulated phone sizes; physical touch and broad controller compatibility remain unverified.

Run `npm ci --prefix apps/system/gcode-preview --ignore-scripts` before building with the shared public-app builder. Each window owns its WebGL preview and resize observer and disposes them when closed.

The build pins a narrow upstream patch that exports the library’s existing parser to the worker. The app uses the same library to render the resulting commands; review the patch and its hash when upgrading `gcode-preview`.

Equivalent relative and absolute paths were compared for coordinates, layers and rendered pixels in local desktop and emulated-phone tests; a live emulated-phone account workflow opened and recovered a relative file. Physical touch, machine behavior and other controller dialects remain unverified.

Local worker and desktop/phone-sized rendering tests compare equivalent inch and metric paths and equivalent coordinate-reset and absolute paths, including unit changes, extrusion and an XY arc. A 4K-sized viewport test covers the same file workflow. These comparisons do not establish controller or physical-machine compatibility.
